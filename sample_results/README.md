## Source
- **Where the runs came from:** one run of the sampling demo (`python -m examples.run_tests`) on 2026-11-08, on Windows 10 with Python 3.11, using an earlier commit of this repository. The archive format has not changed since. The demo saved the runs to the local archive `results/ammeter_results.sqlite3`. That archive is not committed.
- **How they were exported:** with `python -m src.archive_cli export RUN_ID sample_results/<name>_run.json`. Each file is the complete archived run, exactly as `show` prints it: the effective settings, every attempt with its timing, and the statistics.
- **Settings used:** the shipped `config/config.yaml`: 5 Hz, `measurements_count` 10, `total_duration_seconds` 3.0, `request_timeout_seconds` 1.0, emulators on 127.0.0.1.
- **Outcome:** every run made 10 attempts, all successful, with no skipped slots. Each stopped with `count_reached` after about 1.8 s.

## How to read them
- **Random values:** the measurements are **random values generated by the emulators**, not readings of a real current. Each emulator draws its inputs at random on every request: voltage and resistance for Greenlee, magnetic field and calibration factor for ENTES, sampled voltages for CIRCUTOR. Their value ranges differ widely; for example, ENTES returns tens of amperes, while CIRCUTOR returns hundredths.
- **Statistics:** the metrics describe the spread of these random values within each run. They are not accuracy measurements, and they do not show that one device is more accurate than another. There is no known true current to compare against.
- **Timing:** timings and lateness depend on the machine and its load. They are examples, not guarantees.

## Performance report
`greenlee_performance.json` is the [performance consistency report](../README.md#performance-consistency-report) for the Greenlee run above, `503ea15b-e9b0-42a6-af17-c36aeb520856`. It was generated from the local archive that holds that run, which is identical to `greenlee_run.json`.

- **Command:** run in Git Bash from the project root:
  ```bash
  python -m src.archive_cli performance 503ea15b-e9b0-42a6-af17-c36aeb520856 --max-start-lateness 0.005 --max-failure-rate 0 --max-skipped-slot-rate 0 > sample_results/greenlee_performance.json
  ```
- **The three limits are example values chosen for this demonstration** (5 ms maximum start lateness, no failures, no skipped slots). They are not assignment requirements or recommended acceptance criteria. The run passed all three, so the command exited 0.
- **Redirecting on Windows:** Windows PowerShell 5.1 writes UTF-16 when output is redirected with `>`, so use Git Bash, or `cmd /c "... > file"`.
- **Reproducing without the archive:** `tests/test_performance.py` rebuilds the report from the committed `greenlee_run.json` with the same limits and checks that it equals this file.
- **What it shows:** on this run (Windows 10, 5 Hz, 10 attempts), the start lateness was at most about 0.67 ms, and request durations ranged up to about 24 ms. These describe that run on that machine; they are not a timing guarantee.

## HTML report
`greenlee_report.html` is the [HTML run report](../README.md#html-run-report-with-charts) for the same Greenlee run, `503ea15b-e9b0-42a6-af17-c36aeb520856`. Open it in any browser; it needs no network access.

- **Command:** run from the project root against the local archive that holds the run (identical to `greenlee_run.json`), with no limits:
  ```bash
  python -m src.archive_cli plot 503ea15b-e9b0-42a6-af17-c36aeb520856 sample_results/greenlee_report.html
  ```
- **Reproducing without the archive:** `tests/test_visualization.py` renders the committed `greenlee_run.json` and checks that the result is identical to this file.
- **What it shows:** 10 successful readings, no failures, no skipped slots. Start lateness was below 1 ms and request durations were up to about 24 ms. The current values are random emulator output.

## Fault-simulation run
**Simulation data, not a measurement of any device.** These three files come from one run of the [fault-simulation demo](../README.md#fault-simulation-demo), run `209420e5-53e9-4771-b1a2-8a6f4060927a`, device `fault-sim:greenlee:basic-recovery:v1`:

| File | Content |
|---|---|
| `fault_simulation_run.json` | the archived run, exported with `python -m src.archive_cli --db <archive> export 209420e5-53e9-4771-b1a2-8a6f4060927a sample_results/fault_simulation_run.json` |
| `fault_simulation_scenario.json` | the scenario record the demo wrote as `<run_id>.scenario.json`: scenario, settings, server connection log, cleanup evidence, expected vs. observed outcomes, verdict |
| `fault_simulation_report.html` | the HTML report the demo wrote as `<run_id>.html`, with the scenario section |

- **Source:** `python -m examples.fault_simulation --db <temporary archive> --output-dir <temporary directory>` on 2026-11-10, Windows 10, Python 3.11.3, on this branch. The scenario record and report were copied under the names above; the archive is not committed.
- **Outcome:** verdict `pass`. Attempts 1 and 5 succeeded with random Greenlee values; attempt 2 got `InvalidMeasurementError` (not a number: `'12.3.4'`), attempt 3 `InvalidMeasurementError` (empty response, after an orderly close), attempt 4 `AmmeterTimeoutError` after the 1 s timeout. Attempt 4 occupied the schedule for a second, so 2 slots were skipped. The server's delayed reply was interrupted by cleanup and never sent, which is expected. Cleanup stopped 5 of 5 handlers and closed every socket in about 31 ms.
- **What varies:** the order of outcomes is repeatable, but the current values, the port, the timings and the number of skipped slots differ between runs.
- **Reproducing without the archive:** `tests/test_fault_scenario.py` checks that the record belongs to the run, recomputes the comparison from the committed data, and re-renders the report from the two JSON files, which must match `fault_simulation_report.html` exactly.

To compare two of these runs, or list them, use the commands in the main [README](../README.md#querying-the-archive-command-line) with a local archive that contains them. The JSON files themselves are standalone and need no database.
